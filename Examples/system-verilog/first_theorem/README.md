# From a SystemVerilog module to its first kernel-checked theorem

This directory is a worked recipe for an engineer who knows SystemVerilog and a little Lean. It takes a module from
its source file to a theorem the Lean kernel checks, for every value of the module's width parameter. There are two
worked examples, both small designs written for this page:

| File | What it is |
|---|---|
| `dff_arst.sv` | clocked: a `W`-bit D register with an active-low asynchronous reset |
| `dff_arst.sv.json` | its envelope (generated by the extractor, never edited) |
| `dff_arst_proof.lean` | its step contract, for every `W`, every reachable state and every 4-state input row |
| `half_add.sv` | combinational: `W` half adders written with continuous assignments |
| `half_add.sv.json` | its envelope (generated) |
| `half_add_proof.lean` | its contract, for every `W`: known inputs `u`, `v` give `s = u ^ v` and `c = u & v` |

Both proof files build with `lake build` and are targets of the SystemVerilog push gate (`tools/sv_push_gate.txt`).
To start on your own module, copy the proof file of the same kind and follow the steps below.

**What the two theorems say, in plain words.**

* `dff_step` (clocked): for every width `1 ≤ W < 2^30`, from every coherent state of the design (the x start state
  and every state a run reaches from it), on every typed input row (any subset of `clk`, `rst_n`, `d` changing, each
  at its declared width, each bit 0, 1, x or z), one step of the semantics succeeds, the next state is coherent
  again, and the register's next value is `dfNext`: if the clock rose or the reset fell (IEEE 1800-2023 §9.4.2, x
  and z rows included), then `0` when `!rst_n` reads true and `d` otherwise; else `q` holds. The corollaries
  `dff_reset`, `dff_load` and `dff_hold` state the three cases separately.
* `ha_correct` (combinational): for every width `1 ≤ W < 2^31`, in every snapshot of every run (every schedule, every
  stimulus), if the inputs hold known values `u` and `v` then `s` holds `u ^ v` and `c` holds `u & v`. A snapshot in
  which an input bit is x or z is not constrained by this statement.

## 0. Setup

Work from the repository root. The Lean toolchain is the one in `lean-toolchain`. The extractor needs `python3.12`
with `pyslang` 11.x (the frontend every envelope records).

```console
$ python3.12 extractors/sv/extract.py --top dff_arst Examples/system-verilog/first_theorem/dff_arst.sv \
      -o Examples/system-verilog/first_theorem/dff_arst.sv.json     # the envelope
$ lake env lean Examples/system-verilog/first_theorem/dff_arst_proof.lean   # messages and goals while you work
$ lake build Examples/system-verilog/first_theorem/dff_arst_proof.lean      # must end "Build completed successfully"
```

The envelope is the parser's (Slang's) tree of the file, converted node for node. Give the extractor a
repository-relative source path: the envelope records that path and the source's SHA-256, and
`harness/sv_round_trip.py` regenerates every committed envelope from them and compares byte for byte. Never edit an
envelope, and never edit the RTL to get past a tool: a refusal is a gap in the tool (section 6).

`load_design_sv2 X from "path/to/x.sv.json"` reads the envelope at elaboration time (the path is relative to the
package root). Before it defines anything it replays the elaboration at the parameter defaults and refuses the
envelope if it disagrees with Slang's own metadata. It then defines, with one explicit `Nat` argument per module
parameter in declaration order:

* `X.pdesign`: the envelope as a literal Lean term, which proofs can unfold;
* `X.e P…`: the design on the canonical route (`Res CoreMemDesign`; `.ok E` when the route instantiates it at those
  parameters). The clocked stages and the step function `E.step` work on it;
* `X.sem P…`: the design on the scalar semantic family (`Design2`). The combinational stages and the runner `run2`
  work on it.

## 1. Before you start: is the module inside what the tactics read today?

Clocked, admitted: `always_ff @(posedge clk)` and `always_ff @(posedge clk or negedge rst_n)` processes, several of
them, on either clock edge, and on several clocks (state the structure over instants, `SeqDesignI`); the plain
`always @(posedge clk)` and `always @(posedge clk or negedge rst_n)` spellings, with the clock written first in the
event list (`seq_cycle/plain_proof.lean`); `if`/`case` bodies with nonblocking assignments; whole-signal continuous
assignments; `parameter int` and `parameter int unsigned` widths (`seq_cycle/unsigned_proof.lean`; give both bounds
of each dimension as hypotheses); a conditional generate, one structure theorem per arm with the arm's condition as a
hypothesis (`seq_cycle/gen_proof.lean`); memories written at a run-time address. The clocked examples under
`Examples/system-verilog/seq_cycle/` and `seq_multi/` show these.

Clocked, refused today (the messages are in section 6):

* a generate loop, and any child module instance;
* a plain `always` whose event list is not one clock edge with an optional reset edge, or that names the reset first;
* a function call, a procedural `for` loop in an edge process, a continuous assignment to a bit or part select.

Combinational, admitted: continuous assignments and `always_comb`, generate loops, packed arrays of any dimension.
Refused: an unpacked array whose size depends on a parameter (pinned in
`Examples/system-verilog/comb_mem/comb_errors.lean`).

If the module is outside, stop and report the refusal message with the construct: that is a tool gap, not something
the proof can fix.

## 2. A clocked module: the step contract (`dff_arst_proof.lean`)

What you prove: for every state the design can be in and every input row, one step of the semantics succeeds and the
registers afterwards are exactly a function you write down. A *row* is one change of the inputs: a clock edge, a
reset change, a data change, or several at once.

**Step 1. Structure** (one line of proof).

```lean
-- Examples/system-verilog/first_theorem/dff_arst_proof.lean (excerpt)
theorem dff_structure (W : Nat) (h1 : 1 ≤ W) (h2 : W < 2 ^ 30) : SeqDesignI (dff.e W) := by
  sv_structure
```

`sv_structure` instantiates the design at symbolic parameters, checks that every process is an edge process the
clocked theory covers (the instant profile `SeqProfileI`), and checks the side conditions (`seqOblI`: one driver per
signal, no event source read as data, no event source driven by the design, …). Give every `int` parameter a lower
and an upper bound as hypotheses. For a single clock you can state `SeqDesign (X.e P…) "clk"` instead.

**Step 2. Look at the design as the tool sees it.** In a throwaway `example` with `hE : X.e W = .ok E`, run
`sv_seq_inst [dff.e, dff.pdesign] at hE` and then `trace_state`. `hE` now shows the declarations in order (with their
widths) and the processes. Write the view, one value per declaration, in that order, with the names exactly as shown:

```lean
-- Examples/system-verilog/first_theorem/dff_arst_proof.lean (excerpt)
def dfView (c r d q : LVec) : SvState := [("clk", c), ("rst_n", r), ("d", d), ("q", q)]
```

**Step 3. Let the tool compute one step.** State the inputs as a row of new values (every input, in declaration
order), give every width as a hypothesis, and put `trace_state` after it:

```lean
-- Examples/system-verilog/first_theorem/dff_arst_proof.lean (excerpt)
  sv_seq_cycle hcyc : E.slotV (dfView c r d q) mv [("clk", c1), ("rst_n", r1), ("d", d1)] using hE
      [dfView, hc, hr, hd, hq, hc1, hr1, hd1]
```

`hcyc` is the behaviour of your design, computed from the semantics' own definitions. For `dff_arst` it reads:

```text
hcyc :
  E.slotV (dfView c r d q) mv [("clk", c1), ("rst_n", r1), ("d", d1)] =
    Res.ok
      ([("clk", c1), ("rst_n", r1), ("d", d1),
          ("q",
            if
                isPosedge (c.bits[0]?.getD Logic.lx) c1.bits[0] = true ∨
                  isNegedge (r.bits[0]?.getD Logic.lx) r1.bits[0] = true then
              if (evalUnaryOp UnaryOp.lnot r1).condTrue = true then LVec.ofBitVec 0#W else d1
            else q)],
        mv)
```

Each register's next value is a nest of `if`s over the edge tests (`isPosedge old new`, `isNegedge old new`: the
§9.4.2 table, with its x and z rows) and over the conditions of the body (`condTrue`: an `if` whose condition is x
or z runs its `else` branch, §12.4). Read it. If it is not what you expected from the RTL, you have found something.

**Step 4. Write the contract function** from `hcyc` (`dfNext` in the example, a few lines), and the slot equation
`dff_row`, whose statement is `hcyc` with your function on the right. Its proof is the two steps above and three lines
(`seqE_getElem_zero` turns `c1.bits[0]` into the `getD` form the contract uses):

```lean
-- Examples/system-verilog/first_theorem/dff_arst_proof.lean (excerpt)
  rw [hcyc]
  simp only [seqE_getElem_zero, dfView, dfNext, rise, fall, b0]
  rfl
```

**Step 5. Copy sections 3 and 4 of the example** (`dff_facts`, `dff_step`, `dff_start`) and change the names, the
number of signals and the widths. They are plumbing: the shape of a state's view, the list of inputs, and the
library's refinement theorem `CoreMemDesign.step_seqI`, which carries the view-level equation to the step function
`E.step` on real states. `dff_step` is the theorem.

**Step 6. State the clauses a reviewer wants to read** as corollaries of the contract function (`dff_reset`,
`dff_load`, `dff_hold`); each is one `simp`.

**Step 7. Non-vacuity and axioms** (section 4).

What you wrote yourself: the view (one line), the contract function, three statements and the corollaries. The rest
is the example with the names changed.

**What the theorem says about x and z: everything.** Values are 4-state vectors (`LVec`); nothing is assumed known.
For this register: the process fires when the clock rises (0→1, 0→x, 0→z, x→1, z→1) or the reset falls (1→0, 1→x,
1→z, x→0, z→0). When it fires with the reset at 0 the register clears. When it fires with the reset at 1, x or z it
loads `d` bit for bit (x and z included): a reset that falls 1→x fires the process and loads `d`, because `!x` is x
and an `if` on x runs its `else` branch. Otherwise it holds, also while the reset stays at 0 without an event.

**Coherent states.** The hypothesis `E.Coherent st` says the state is well formed: every signal has its declared
width and the internal cache agrees with the store. The start state is coherent (`dff_start`) and every step returns a
coherent state (`dff_step`), so every state of every run is covered. Keep this hypothesis: a statement over all state
records also talks about records no run reaches, and cannot be proved.

## 3. A combinational module (`half_add_proof.lean`)

What you prove: in every snapshot of every run, under every schedule, if the inputs hold known values then the
outputs hold your function of them.

1. **Structure.** `sv_structure (rank := rippleRank (fun p => p) (fun _ _ _ => 0))` proves
   `CombDesign (X.sem W) ∧ Acyclic (X.sem W)`: every process is combinational and there is no combinational loop.
   The rank orders the processes so that each reads only lower ones; for assignments in source order `fun p => p`
   works.
2. `refine Models2.of_comb_pointwise hc (fun st heqs hsh => ?_)` reduces "every run" to one settled snapshot.
3. `sv_equations` puts the design's equations in the context, per signal and per bit:
   `eq_s_1 : ∀ k, k < W → st.boolAt "s" k = …` and `known_s_1` (the bit is known). `trace_state` shows them.
4. Your mathematics: rewrite each output with `lookup_bv known_s_1`, then bit by bit with
   `BitVec.eq_of_getLsbD_eq`, the equations, and `SvState.boolAt_ofBitVec` for the inputs.
5. The side goals (the parameter's range, "this input bit is known") close with the three-line `first | …` block.

**What the theorem says about x and z.** The statement is conditional on known inputs (`LVec.ofBitVec u`). That is
the honest reading of "the outputs are f(inputs)" for an adder; a claim about how x propagates needs a statement of
its own. The `#guard` at the top of the file runs a row with an x and a z input bit.

## 4. Non-vacuity: a run, a wrong contract, the axioms

A theorem can be true for a bad reason (contradictory hypotheses, a design that never runs). Each file carries checks
against that.

* **A run.** A `#guard` runs the compiled design on a short stimulus with x and z in it and compares the outputs
  (section 6 of `dff_arst_proof.lean`: 12 rows; the top of `half_add_proof.lean`: 2 rows). The theorems are about a
  design that runs, and the rows agree with a simulator (Oracle, below).
* **A wrong contract must fail.** `dff_arst_proof.lean` keeps `dfSync`, the contract of a register with a synchronous
  reset, and checks with `fail_if_success` that the last three lines of the `dff_row` proof do not close the slot
  equation stated with it. Do the same by hand for your own contract: change one case of the function and check that
  the slot equation stops at `rfl`. For `dfSync` the message shows the design's asynchronous term against the
  contract's:

  ```text
  error: Tactic `rfl` failed: The left-hand side
    Res.ok
      ([("clk", c1), ("rst_n", r1), ("d", d1),
          ("q",
            if
                isPosedge (c.bits[0]?.getD Logic.lx) (c1.bits[0]?.getD Logic.lx) = true ∨
                  isNegedge (r.bits[0]?.getD Logic.lx) (r1.bits[0]?.getD Logic.lx) = true then
              if (evalUnaryOp UnaryOp.lnot r1).condTrue = true then LVec.ofBitVec 0#W else d1
            else q)],
        mv)
  is not definitionally equal to the right-hand side
    Res.ok
      ([("clk", c1), ("rst_n", r1), ("d", d1),
          ("q",
            if isPosedge (c.bits[0]?.getD Logic.lx) (c1.bits[0]?.getD Logic.lx) = true then
              if (evalUnaryOp UnaryOp.lnot r1).condTrue = true then LVec.ofBitVec 0#W else d1
            else q)],
        mv)
  ```

* **The axioms.** The files end with `#print axioms` of every theorem. The answer must be `propext`,
  `Classical.choice`, `Quot.sound` (or a subset): no `sorryAx`, no `Lean.ofReduceBool`.

## 5. What each tactic and theorem does

| Name | What it does |
|---|---|
| `load_design_sv2 X from "…json"` | reads the envelope into Lean; defines `X.pdesign`, `X.e …`, `X.sem …` (section 0) |
| `sv_structure` | clocked goal `SeqDesignI (X.e …)` or `SeqDesign (X.e …) "clk"`: the instantiation at symbolic parameters, the profile, the obligations. Combinational goal `CombDesign … ∧ Acyclic …`. Every refusal names its reason |
| `sv_interface` | clocked goal `SeqPorts (X.e …) ins outs`: the ports and their widths |
| `sv_seq_inst [X.e, X.pdesign] at hE` | turns `hE : X.e … = .ok E` into `hE : <the explicit design> = E`: the equation "the loaded design is exactly these declarations and processes" |
| `sv_seq_cycle h : E.slotV v mv row using hE [facts]` | computes one step on a symbolic view: `h : … = .ok (…)` |
| `sv_domains` | (optional) the design's clock events, which register belongs to which, and the reads that cross between them |
| `seq_mirror` | (optional) computes the instantiation once and caches it, so a file with many theorems stops repeating it |
| `sv_equations` | combinational: the per-bit equations and knownness facts of a settled snapshot |
| `CoreMemDesign.step_seqI` | a theorem, not a tactic: a view-level slot equation gives the real step |

Nothing here is trusted: each tactic is `simp` and `omega` steps that the kernel checks. The docstrings of
`LeanModels/Sv/SeqCycleStages.lean` and `LeanModels/Sv/SeqCycleTactic.lean` are the reference.

## 6. Common refusals and what to do

The quoted messages were produced by the tree this directory is in, each on a small module with the one construct
(the parameter-sized unpacked array by the example that pins it).

Clocked (`sv_structure` on `SeqDesignI (X.e …)`):

* ``sv_structure: the instantiation does not normalize at these parameters: <reason>, refused``: the reason is a
  generate loop (a tool gap: report it), a constant expression with an operator the pass does not evaluate (a tool
  gap), or a generate condition the hypotheses in context do not decide (add the hypothesis on the parameter).
* ``sv_structure: the route does not instantiate this design at these parameters; its outcome: (do …`` followed by
  a long term: the instantiation could not be computed for another reason. A child module instance gives the short
  form ``its outcome: X.e = Res.timeout``. First check that every parameter has both bounds as hypotheses;
  otherwise it is a tool gap: report it with the construct.
* ``sv_structure: process 0 is a plain `always` whose event list is not one clock edge with an optional
  asynchronous reset edge …``: three or more edges, or a level-change event (`always @(a or b)`). A plain `always`
  that names the reset first (`@(negedge rst_n or posedge clk)`) fails at obligation `oblNoSourceRead`: the first
  edge is read as the clock.
* ``sv_structure: process 0 (an edge process) has a procedural `for` loop: the memories slice (next), refused``.
* ``sv_structure: process 0 is a continuous assign to a select or concatenation target: outside the clocked
  profile``.
* ``sv_structure: obligation `oblConverted`: an expression ingestion kept unconverted (a user function call, U5),
  refused``: a function call.
* ``Tactic `rfl` failed: The left-hand side … is not definitionally equal to the right-hand side`` at the end of the
  slot equation: your contract function is not the design's (section 4). Compare it with `hcyc`, term by term. If
  `hcyc` shows `x.resizeU W` where you expected `x`, a width hypothesis is missing from the bracket list of
  `sv_seq_cycle`.
* ``Tactic `simp` failed with a nested error: (deterministic) timeout … maximum number of heartbeats``: the
  instantiation is expensive. Raise the limit for that theorem (`set_option maxHeartbeats 4000000 in`, as the
  examples do); a small memory with a `for` loop in its reset branch needed it before its real refusal (the `for`
  loop message above) appeared. If it still times out, try a concrete parameter point to see the refusal, and report
  it.
* `dff_facts` fails at its `rcases v with …` line: the view has the wrong number of signals or the wrong order (the
  pattern has one `⟨⟨n, x⟩, _ | …⟩` per declaration).

Combinational:

* ``sv_structure: outside the supported fragment — declaration `stage`: unpacked array storage whose shape depends on
  a parameter (UnpackedDecl:memory) …``: a parameter-sized unpacked array (`stage` is the array's name;
  `Examples/system-verilog/comb_mem/comb_errors.lean` pins the full message); a tool gap.
* Unsolved side goals after `sv_equations`: a parameter range (`intros; omega`) or an input knownness goal
  (`refine inKnown_ofBitVec hA ?_; omega`, one alternative per input hypothesis).
* `omega` fails on a width: rewrite the declared width first
  (`have hWd : (↑W + -1 : Int).natAbs + 1 = W := by omega`, then `rw [hWd] at …`).

## 7. Rules

* No `sorry`, no `admit`. `native_decide` and `bv_decide` only with a one-line reason at the use site and the
  theorem's `#print axioms`; neither example uses them.
* The statement is about the loaded envelope, unmodified, and the RTL as written.
* Parameters stay symbolic. A theorem at `W = 8` only is a different, weaker theorem: say so if that is what you
  prove.
* Do not weaken a statement to make a proof go through. If a hypothesis turns out to be needed, that is a finding
  about the design or the semantics: report it.

## Oracle

Icarus Verilog 12.0 (stable), `iverilog -g2012`, on the stimuli of the two `#guard`s at `W = 4`. The register's
testbench (the first `#1` lets the process reach its event control before the inputs change; the design starts all
x, as in the semantics):

```systemverilog
`timescale 1ns/1ps
module tb;
  logic clk, rst_n; logic [3:0] d; wire [3:0] q;
  dff_arst #(.W(4)) dut(.clk(clk), .rst_n(rst_n), .d(d), .q(q));
  task show; $display("%b", q); endtask
  initial begin
    #1;
    rst_n = 1; clk = 0; d = 4'b0101; #1 show;
    clk = 1;                         #1 show;
    rst_n = 0;                       #1 show;
    clk = 0; rst_n = 1;              #1 show;
    clk = 1'bx;                      #1 show;
    d = 4'bxxxx;                     #1 show;
    clk = 1;                         #1 show;
    d = 4'b0011; rst_n = 1'bx;       #1 show;
    rst_n = 0;                       #1 show;
    rst_n = 1'bz; d = 4'b1010;       #1 show;
    clk = 0;                         #1 show;
    clk = 1'bz;                      #1 show;
    $finish;
  end
endmodule
```

It prints `xxxx 0101 0000 0000 0101 0101 xxxx 0011 0000 0000 0000 1010`, one value per row, the same as the
`#guard`. The half adders' two rows (`a = 0101, b = 0110` and `a = 01xz, b = 0110`) print `s c` = `0011 0100` and
`00xx 01x0`, the same as the `#guard`. These are the only oracle rows. The theorems themselves are over every width,
state and input, which no simulation covers.
